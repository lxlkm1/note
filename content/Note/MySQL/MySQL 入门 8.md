# 1 事务

>[!note] 概述
>事务就是把好几条sql 语句变成一个不可分割的整体，要不里面操作全部成功，要不里面操作全部失败，常用于转账等情景


>[!danger] 误解
>用于大多数课本介绍事务都使用转账的例子，所以就很容易误解成只有修改数据的时候才需要事务，实际是读取数据库的查询操作也需要事务，如果读取操作没有使用事务，我在数据库读取xx仓库的物品库存，第一次查询到xx仓库库存，第二次我再查询一次，可能在这个之间，这个数据可能被改动了，这样就会导致两次读取的数据不一样，如果我们使用了事务，在查询事务没有结束之前，这个数据不能被修改

## 1.1 如何使用事务

>[!note] 背景补充
>在MySQL 里面有一个名为 autocommit 的系统变量，这个系统变量为1的时候，在没有使用BEGIN 等关键词显性开启事务的情况下，每个单独的SQL 语句会被单独当成事务，并且自动提交，并且这个系统变量默认情况下为1


>[!note] 代码解释
>BEGIN 在该会话窗口显性开启一个事务，只要该事务没有被提交，其他会话窗口看不到该事务的修改,在SQLYOG 一个连接的多个窗口还是同一个会话，想要验证多开几个客户端

```mysql
-- 开启事务
BEGIN;
[各种sql语句]
-- 提交语句
COMMIT;
```

### 1.1.1 事务回滚

>[!note] 我怎么判断我在哪里遇到错误，发现错误再回滚，而不是把回滚写死
>其实什么时候决定使用使用回滚取决于后端代码，try catch


如果在事务中，出现了错误，比如服务器断电什么的，我们应该使用回滚操作，让数据库数据回到事务开始之前的状态，或者可以指定一个保存点，如何回到保存点状态也行。

```mysql
-- 开启事务
BEGIN;
try:

[各种sql语句]
SAVEPOINT [保存点名字];
[各种sql语句]
-- 假设这里出现错误
-- 如果没有保存点名字就直接回到开启事务之前最近的状态
ROLLBACK [保存点名字];

[各种sql语句]
-- 提交语句
COMMIT;

```

### 1.1.2 设置隔离等级

>[!note] 知识补充
>隔离等级的设置是为了允许我们在事务一致性和数据库性能之间平衡，隔离等级越高，事务一致性就越强，但是数据库性能会更低

```mysql
/* MySQL 支持四种隔离等级
   READ UNCOMMITED 可以读取没有被提交的，会导致脏读,不可重复读，幻读
   READ COMMITDED 不会导致脏读，但是会导致不可重复读，幻读
   REPEATABLE READ 仍然有幻读
   SERIALIZABLE 解决所有问题，但是性能低下
*/
SET [GOBAL/SESSION] TRANSACTION ISOLATION LEVEL [隔离等级]
```


## 1.2 事务的四大特性


### 1.2.1 原子性

原子性就是把几条SQL 语句变成一个不可分割的个体，要不都执行，要不都不执行

### 1.2.2 隔离性

隔离性就是把同时执行的事务相互分开，比如事务A 修改一张表的第n行，还没有提交，而事务B 也想修改同个数据，这个时候就阻止事务B 修改这个数据，直到事务A 提交，防止数据库混乱

### 1.2.3 一致性

这里的一致性指的是规则的一致性，就是我们可以指定一个规则，比如账户表，小王的余额和小赵的余额加在一起是1000，起初小王余额是300，小赵余额是700，符合规则，所有保持了一致性，后面经过一个转账事务，小王余额是900，小赵是100，加在一起仍然是1000，仍然符合规则，这个个就是一致性

### 1.2.4 持久性

持久性指的是事务单一旦被提交，这个被提交的内容就不会丢失，比如提交的事务不会因为服务器断电而丢失

### 1.2.5 总结

数据库一致性和持久性是我们实现的目标，而原子性和隔离性是我们的方法


## 1.3 事务常见问题

危害性

>  脏写 > 脏读 > 不可重复读 > 幻读 

### 1.3.1 脏写

_> 脏写就是两个事务A，B 同时修改一个数据，B 修改了这个数据，但是没有提交，A 读取了这个没有被修改的数据，然后提交了，随后B 也提交了，覆盖了A 提交的数据，而没有在A 提交的数据上去修改

### 1.3.2 脏读

_> 脏读就是在有多个事务情况下， 事务A 修改了数据，但是没有提交，但是没有提交的数据被事务B 读取到了，这个就是脏读

### 1.3.3 不可重复读

>[!note] 为什么这个问题叫做不可重复度
>因为该数据重复读取到的内容不一致，所以为了防止有人重复读取，就给这个问题命名成不可重复读，就是不能重复读取的意思

_> 不可重复读指的就是在脏读就是在有多个事务情况下， 事务A 先读取数据，事务B 修改了数据提交了，事务A 又读取一遍这个数据，发现数据改变了，正常情况下应该先让事务A 读完两次数据再让事务B 去提交数据

### 1.3.4 幻读

_> 幻读和不可重复读唯一的全部就是事务B 增加了数据，而不是修改数据，事务A第二次读取事务多出了好多数据



# 2数据库导出

>[!note] 基本知识
>
>数据库导出有两种方式，一种是直接把数据库文件保存出来，另外一种是把数据库全部数据以sql 脚本文件形式保存出来，一般情况下使用sql 脚本文件比较方便，而mysql 官方提供了一个叫mysqldump 的工具帮我们导出数据库


## 2.1 指令


导出数据库
```bash
# 导出指定数据库
mysqldump -u ][用户名] -r -p [数据库名字] > [输出文件位置]

# 导出全部数据库
mysqldump -u ][用户名] -r -p —A> [输出文件位置]
```

导出表格
```bash
# 导出表格
mysqldump -uroot -p [数据库名字] [表名字] -where=[导出数据符合的条件]  > [输出文件位置]
```

恢复数据库

恢复数据库就是把导出的sql文件在服务器上执行一遍就好了
