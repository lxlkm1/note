# 1 SQL 基础 

## 1.1 数据类型

> [!note] 知识点标签：#分类/数据类型
> MySQL 中的核心数据类型主要分为数值、字符串和时间日期三大类：
> 1. `INT`：用于存储标准整数。
> 2. `VARCHAR`：用于存储可变长度的字符串。
> 3. ...（更多类型如 `DATETIME`, `DECIMAL` 等在后续深入场景中使用）

## 1.2 命令行登录

> [!warning] 语法陷阱
> MySQL 命令行解释器下的绝大部分 SQL 指令必须以分号 `;` 结尾。如果没有输入分号直接回车，解释器会换行等待输入，而不是执行命令。

```bash
# -u 指定用户名，-p 提示输入密码
mysql -u root -p
```

## 1.3 命令行退出

```bash
# 退出 MySQL 客户端解释器
exit
```

## 1.4 查看数据库

```sql
-- 不要丢失单词末尾的 's'
SHOW DATABASES;
```

## 1.5 查看表结构

```sql
-- DESCRIBE 的简写，用于查看表的字段、类型、主键等元数据信息
DESC [表名];
```

## 1.6 创建数据库

> [!danger] 环境与重名隐患（坑点）
> 1. 在 Windows 环境下，MySQL 的数据库名称默认不区分大小写；而在 Linux 环境下默认区分大小写。为保证跨平台一致性，建议所有数据库名和表名统一使用小写。
> 2. 创建数据库前应确认无同名库，或者使用 `IF NOT EXISTS` 语法防止报错拦截。

```sql
CREATE DATABASE [数据库名];
```

## 1.7 选择数据库

> [!info] 作用域说明
> `USE` 命令用于切换当前操作的上下文。执行此命令后，所有的查询、建表等 SQL 操作默认都将基于该数据库进行，直到再次执行 `USE` 切换到其他库。

```sql
USE [数据库名];
```

## 1.8 查看表格

```sql
-- 查看当前所选数据库中的所有表
SHOW TABLES;
```

## 1.9 创建表格

```sql
CREATE TABLE [表名] (
    [列名_1] [数据类型_1],
    [列名_2] [数据类型_2],
    ...
);
```

## 1.10 数据定义与操作

### 1.10.1 查询数据

```sql
-- 仅作为演示，生产环境严禁直接使用 SELECT *
SELECT * FROM [表名];
```

### 1.10.2 插入数据

```sql
-- 插入指定列的数据，值的顺序必须与列名顺序一一对应
INSERT INTO [表名] ([列名_1], [列名_2]) VALUES ([值_1], [值_2]);
```

### 1.10.3 删除数据表

```sql
-- 永久删除表结构及其内部所有数据（极高危操作）
DROP TABLE [表名];
```

### 1.10.4 删除数据库

```sql
-- 永久删除整个数据库（极高危操作）
DROP DATABASE [数据库名];
```

## 1.11 重置 root 用户密码

> [!warning] 权限要求
> 执行跳过权限表的启动命令时，必须确保当前的终端（命令行/PowerShell）拥有管理员权限（Administrator）。

```bash
# 以控制台模式启动 MySQL 守护进程，跳过权限表并共享内存，用于免密登录后修改 root 密码
mysqld --console --skip-grant-tables --shared-memory
```


# 2 理论思考延伸

> [!note] 知识点标签：#分类/架构原理
> 1. **为什么客户端使用 TCP 而不是 UDP？**
>    数据库交互需要极高的数据完整性与顺序性。TCP 提供可靠连接、丢包重传和错误校验，保证 SQL 语句和结果集不会在网络传输中残缺，而 UDP 无法保证这一点。
> 2. **什么是线程池？**
>    为了避免频繁创建和销毁线程带来的系统开销，MySQL 预先实例化一定数量的线程缓存在“池”中。当客户端发起连接请求时，直接从池中分配闲置线程处理请求，处理完毕后线程归还池中，极大提升了高并发下的响应吞吐量。
> 3. **MySQL 服务层包含什么？**
>    服务层（Server 层）是 MySQL 的大脑，包含连接器（权限验证）、查询缓存（MySQL 8.0 已废弃）、分析器（词法与语法分析）、优化器（生成执行计划）和执行器（调用存储引擎 API 获取数据）。
> 4. **Windows 注册表的作用？**
>    在 Windows 环境下将 MySQL 注册为系统服务（Service）后，注册表会记录其启动参数的路径、可执行文件位置（`mysqld.exe`）以及环境依赖，确保系统开机时能正确的后台拉起数据库服务。

# 3 最佳实践与证据

* **字符集与排序规则规范** — 在创建数据库和表时，必须显式指定字符集为 `utf8mb4`，排序规则建议为 `utf8mb4_0900_ai_ci`（MySQL 8.0 默认）。传统的 `utf8`（实际为 utf8mb3）最多只能存储 3 个字节，无法兼容 Emoji 表情符号和一些复杂的生僻汉字，会导致数据截断报错。 (证据：[MySQL 8.0 官方文档 - Character Sets and Collations](https://dev.mysql.com/doc/refman/8.0/en/charset.html))
* **严格模式的开启** — 确保 `sql_mode` 包含 `STRICT_TRANS_TABLES`。如果插入的数据长度超标或类型不符，严格模式会直接报错中断，而不是像老版本那样静默截断数据并插入，这可以从根源上避免“脏数据”入库。 (证据：[MySQL 8.0 官方文档 - Server SQL Modes](https://dev.mysql.com/doc/refman/8.0/en/sql-mode.html))
