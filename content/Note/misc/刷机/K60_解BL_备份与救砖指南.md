# Redmi K60 解 BL、刷 crDroid 前的备份与救砖指南

适用对象：
- 机型：`Redmi K60`
- 代号：`mondrian`
- 场景：准备解 `Bootloader (BL)`、后续刷 `crDroid`

先记住三条硬规则：
- `解 BL` 基本等同于清空手机数据，先备份再操作。
- 只刷 `mondrian` 对应的包，不要混用别的机型文件。
- 在自定义 ROM 上不要重新锁 `BL`，有变砖风险。

## 一、你到底要备份什么

不是只备份照片。对刷机来说，真正容易丢的是下面这些：

1. 账号与认证
- 小米账号
- Google 账号
- 微信登录状态
- 支付宝登录状态
- 银行 App 登录状态
- 双重验证器里的动态验证码

2. 文件与资料
- 照片、视频、录音
- `Download` 下载目录
- `Documents` 文档
- 微信接收的重要文件
- QQ/Telegram/其他 IM 保存的文件

3. 应用数据
- 微信聊天记录
- 便签、短信、通话记录
- 浏览器书签
- 游戏存档
- 阅读器、密码管理器、本地笔记

4. 系统信息
- 当前系统版本号
- Android 版本
- 机型和代号
- IMEI

## 二、最稳的备份方法

目标不是“理论可恢复”，而是“你自己能真的找回来”。

### 方案 A：电脑本地备份

这是最推荐的方式。

操作：
1. 用数据线把手机接电脑。
2. 手机下拉通知栏，把 USB 模式切到 `文件传输 / MTP`。
3. 打开 `此电脑`，进入手机存储。
4. 手动复制这些目录到电脑：
- `DCIM`
- `Pictures`
- `Movies`
- `Music`
- `Download`
- `Documents`
- 你自己存资料的其他目录

建议在电脑新建一个目录，例如：
- `D:\PhoneBackup\K60_2026-04-20`

优点：
- 直观
- 不依赖云端
- 恢复时最快

容易错的地方：
- 只拷照片，没拷 `Download` 和文档。
- 复制过程中断，没检查文件数。
- 线材只能充电不能传数据。

### 方案 B：小米云 + Google 云

适合备份联系人、短信、系统设置、部分 App 数据，但不要只靠云备份。

建议：
- 小米云同步：联系人、短信、便签、相册
- Google 同步：联系人、日历、部分应用设置

容易错的地方：
- 以为“云同步开着”就等于已经同步完成。
- 刷机前没手动进去看最近同步时间。

### 方案 C：微信和 IM 单独备份

微信一定要单独做。

因为很多人刷完机后，最痛的不是照片丢了，而是聊天记录没了。

你至少要做：
- 微信聊天记录迁移到另一台设备，或备份到电脑
- 导出重要文件
- 记住微信登录方式和手机号

其他 IM 也一样：
- QQ
- Telegram
- 钉钉
- 企业微信

### 方案 D：双重验证器单独备份

如果你用了下面这些：
- Google Authenticator
- Microsoft Authenticator
- Aegis
- Authy

那这部分要单独处理，不然刷完机可能连账号都登不回去。

至少做一件事：
- 导出恢复码
- 备份种子
- 迁移到另一台设备

这是刷机前最容易漏掉、后果最严重的一项。

## 三、刷机前你应该记录下来的信息

在手机里记下：
- `设置 -> 我的设备 / 关于手机`
- 当前 `HyperOS` 完整版本号
- 当前 Android 版本
- 存储空间剩余

另外记录：
- IMEI
- SN 序列号
- 小米账号手机号/邮箱

原因：
- 以后回退官方系统时要核对机型和版本线
- 设备异常时你要确认是不是拿错线刷包

## 四、刷机前必须下载到电脑里的文件

至少准备这些：
- `platform-tools`（ADB/Fastboot）
- `crDroid` for `mondrian`
- `OrangeFox / OFOX recovery` for `mondrian`
- 如果是 `Vanilla` 版，额外准备 `GApps`
- `Redmi K60` 官方完整包或线刷包

原则：
- 文件先下载好，再动手机
- 所有文件集中放一个目录
- 下载完成后不要随意改文件名

建议目录：
- `D:\Android\mondrian\`

## 五、怎么确认“我真的备份好了”

不要凭感觉。按下面检查：

1. 电脑里能看到备份目录。
2. 备份目录里能打开几张照片、几个视频、几个文档。
3. 微信聊天记录已经迁移或电脑备份完成。
4. 验证器恢复码已保存到别处。
5. 你能重新登录小米账号、Google 账号、微信。

满足这 5 条，才算“备份完成”。

## 六、如果变砖了，先判断是哪一种

“砖”分很多级，处理办法完全不同。

### 1. 软砖

常见表现：
- 卡开机 Logo
- 无限重启
- 进不去系统
- 但还能进 `Recovery`
- 或还能进 `Fastboot`

这类通常还能救。

### 2. 半砖

常见表现：
- 黑屏
- 无法进系统
- 但电脑偶尔还能识别
- 或能进 `Fastboot` 但刷写异常

这类要看驱动、镜像、分区状态。

### 3. 硬砖

常见表现：
- 黑屏无反应
- 按键无反应
- 充电无明显反应
- 电脑只识别成异常端口，或者完全不识别

这类最麻烦，通常不靠普通 recovery 解决。

## 七、刷完出问题时，按这个顺序排查

### 情况 A：卡开机 Logo，但还能进 Recovery

优先检查：
1. 你刷的是不是 `mondrian` 包。
2. recovery 是不是 `mondrian` 专用。
3. 首刷有没有做 `Format Data`。
4. `Vanilla` 版有没有补刷 `GApps`。
5. 有没有多刷了不该刷的 `firmware`、模块、root 包。

处理思路：
- 回 recovery
- 重新按 `clean flash` 流程刷一次
- 不要混刷多余补丁

### 情况 B：进不了系统，但还能进 Fastboot

这是最关键的“还没彻底死”状态。

你可以做：
1. 在电脑执行：

```bash
fastboot devices
```

2. 如果能识别设备，优先考虑两条路：
- 重新进入 recovery，按正确流程重刷 `crDroid`
- 直接回刷官方系统

如果你只是首刷失败，通常先重刷一次更合理。

如果你已经乱刷过很多东西，建议回官方更稳。

### 情况 C：Recovery 没了，但 Fastboot 还在

这时通常可以：
- 用 `fastboot` 临时启动正确 recovery
- 或重新刷 recovery

核心原则：
- 只用 `mondrian` 的 recovery
- 不要从别的机型“借用”镜像

### 情况 D：黑屏，但电脑还能识别

先做最基础的排除：
- 长按电源 10 到 20 秒
- 尝试 `音量下 + 电源`
- 再尝试 `音量上 + 电源`
- 换线
- 换 USB 口
- 换电脑

如果电脑还能识别到 `fastboot`，说明还不是最坏情况。

## 八、回官方系统的意义

你电脑里必须提前准备官方包，因为它是你的兜底方案。

用途：
- 刷机失败后回退
- 验证是不是第三方 ROM 导致的问题
- 恢复基础可用状态

如果你手里没有官方包，出问题时你会非常被动。

## 九、真正容易导致变砖的错误

下面这些比“刷机本身”更危险：

1. 刷错机型包
- K60 只认 `mondrian`

2. 在自定义 ROM 上重新锁 BL
- 这是高风险行为

3. 首刷忘记 `Format Data`
- 容易卡加密、卡开机

4. 混刷来源不明的 `firmware`
- 可能导致触控、相机、基带异常

5. 一次性刷太多东西
- `ROM + GApps + root + 模块 + 内核 + DFE`
- 出问题时根本无法定位

6. 电脑没识别到 `fastboot` 还硬上
- 先解决驱动，再刷

## 十、最低限度的“救命检查项”

在你真正开始刷机前，电脑上至少要先验证这两条：

系统里：
```bash
adb devices
```

Fastboot 模式里：
```bash
fastboot devices
```

如果第二条不通，不要继续。

## 十一、给你一个现实建议

第一次刷机时，只做最小改动：
- 解 BL
- 刷 recovery
- 刷 `crDroid`
- 必要时刷 `GApps`

先别急着：
- root
- 装模块
- 刷第三方内核
- 改动画、改分区、乱打补丁

系统先稳定跑起来，再谈后续。

## 十二、出问题时的处理优先级

按这个顺序来，不要慌乱乱试：

1. 先判断还能不能进 `Fastboot`
2. 能进 `Recovery` 就先检查刷机步骤
3. 能进 `Fastboot` 就保留救援空间
4. 不要尝试在坏状态下重新锁 BL
5. 实在不稳，回官方包

## 十三、你开始刷机前，最后确认一次

确认以下项目全部满足：
- 已经备份照片、视频、文档
- 已经备份微信和重要 IM 数据
- 已经备份验证器恢复码
- 已记录系统版本号和 IMEI
- 已下载 `mondrian` 对应 ROM 和 recovery
- 已准备官方回退包
- 电脑已能识别 `adb`
- 电脑已能识别 `fastboot`

全部满足后，再继续。
